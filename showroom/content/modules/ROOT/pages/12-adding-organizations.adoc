= Adding a New Organization

[NOTE]
====
Adding a new organization to a running Hyperledger Fabric BFT network is a **multi-phase production operation** that requires genesis block regeneration, orderer restarts, and chaincode lifecycle updates. This guide provides the complete procedure with all commands. **Expect 5-10 minutes of orchestration and ~1-2 minutes of ordering service unavailability** during genesis regeneration.
====

[IMPORTANT]
====
**Bootstrap App Source Repository** — The bootstrap ArgoCD Application (`certchain-bootstrap`) sources from the **public GitHub repository**, not from Gitea. Changes pushed to Gitea only affect the 5 child Applications (central, 3 orgs, showroom). To add a new org, you must update the bootstrap app's source to point to a repository you control:

[.console-input]
[source,bash]
----
# Option 1: Point bootstrap app to Gitea (recommended for this demo)
oc patch application certchain-bootstrap -n openshift-gitops --type=merge \
  -p '{"spec":{"source":{"repoURL":"https://gitea-certchain-showroom.{cluster_domain}/certchain/hyperledger-on-openshift-demo.git"}}}'

# Option 2: Fork the GitHub repo and point bootstrap to your fork
# oc patch application certchain-bootstrap -n openshift-gitops --type=merge \
#   -p '{"spec":{"source":{"repoURL":"https://github.com/YOUR-USER/hyperledger-on-openshift-demo.git"}}}'
----

After this change, pushes to Gitea (or your fork) will trigger ArgoCD to pick up the new org Application definition.
====

== Architecture Overview

The CertChain demo runs 3 organizations (TechPulse, DataForge, NeuralPath) on a 4-node BFT orderer cluster (1 central + 3 org orderers). Adding a 4th organization ("QuantumLeap") requires:

[cols="1,3,1"]
|===
| Phase | Description | Downtime?

| *1. Infrastructure*
| Deploy org namespace via Helm + ArgoCD (peer, orderer, CouchDB, Keycloak, APIs)
| No

| *2. Crypto & Secrets*
| Enrollment runs automatically; copy org secrets to central namespace
| No

| *3. Genesis Regeneration*
| Update `configtx.yaml` with new org + orderer, regenerate genesis block
| *Yes (~1-2 min)*

| *4. Channel Operations*
| Rejoin all orderers with new genesis, join new peer, set anchor peer
| *Yes (during rejoin)*

| *5. Chaincode Lifecycle*
| Install, approve, and commit chaincode with updated endorsement policy
| No

| *6. Identity Brokering*
| Register new org's Keycloak as identity provider in central Keycloak
| No
|===

== Phase 1: Infrastructure Deployment

These steps modify the Git repository to add the new org. Run from the *Terminal* tab.

=== Step 1.1: Clone the repo

[.console-input]
[source,bash,subs="attributes"]
----
cd ~ && [ -d certchain-repo ] || git clone {gitea_url}/certchain/hyperledger-on-openshift-demo.git certchain-repo
cd ~/certchain-repo
git config user.name "Lab User"
git config user.email "lab-user@local.demo"
----

=== Step 1.2: Add org config to bootstrap values

[.console-input]
[source,bash]
----
cd ~/certchain-repo

cat >> helm/bootstrap/values.yaml << 'ORGEOF'

  quantumleap:
    enabled: true
    org:
      name: quantumleap
      displayName: "QuantumLeap Labs"
      mspId: QuantumLeapMSP
      primaryColor: "#dc2626"
ORGEOF

echo "Added quantumleap config:"
grep -A6 "quantumleap:" helm/bootstrap/values.yaml
----

=== Step 1.3: Add org to the application loop

[.console-input]
[source,bash]
----
cd ~/certchain-repo

sed -i 's/list "techpulse" "dataforge" "neuralpath"/list "techpulse" "dataforge" "neuralpath" "quantumleap"/' \
  helm/bootstrap/templates/applications.yaml

echo "Updated org list:"
grep 'orgs :=' helm/bootstrap/templates/applications.yaml

[.console-input]
[source,bash]

  helm/components/certchain-org/values-quantumleap.yaml

----

=== Step 1.5: Push and wait for ArgoCD

[.console-input]
[source,bash]

git push origin main

== Phase 2: Copy Secrets to Central Namespace

The org enrollment job creates secrets in `certchain-quantumleap`. The central namespace needs org-prefixed copies for genesis generation and channel operations.

[.console-input]
[source,bash]
----
CENTRAL_NS="certchain"
ORG="quantumleap"
ORG_NS="${CENTRAL_NS}-${ORG}"
ORDERER_NAME="orderer4"  # Next orderer ID (0=central, 1=techpulse, 2=dataforge, 3=neuralpath)

echo "=== Waiting for org enrollment to complete ==="
for secret in admin-msp peer0-tls orderer-msp orderer-tls; do
  echo -n "  Waiting for $secret in $ORG_NS..."
  while ! oc get secret "$secret" -n "$ORG_NS" &>/dev/null; do sleep 5; echo -n "."; done
  echo " OK"
done

echo ""
echo "=== Copying secrets to central namespace ==="

# admin-msp → quantumleap-admin-msp
oc get secret admin-msp -n "$ORG_NS" -o yaml \
  | sed "s/namespace: $ORG_NS/namespace: $CENTRAL_NS/; s/name: admin-msp/name: ${ORG}-admin-msp/" \
  | grep -v 'uid:\|resourceVersion:\|creationTimestamp:' \
  | oc apply -n "$CENTRAL_NS" -f -

# peer0-tls → peer0-quantumleap-tls
oc get secret peer0-tls -n "$ORG_NS" -o yaml \
  | sed "s/namespace: $ORG_NS/namespace: $CENTRAL_NS/; s/name: peer0-tls/name: peer0-${ORG}-tls/" \
  | grep -v 'uid:\|resourceVersion:\|creationTimestamp:' \
  | oc apply -n "$CENTRAL_NS" -f -

# orderer-msp → orderer4-quantumleap-msp
oc get secret orderer-msp -n "$ORG_NS" -o yaml \
  | sed "s/namespace: $ORG_NS/namespace: $CENTRAL_NS/; s/name: orderer-msp/name: ${ORDERER_NAME}-${ORG}-msp/" \
  | grep -v 'uid:\|resourceVersion:\|creationTimestamp:' \
  | oc apply -n "$CENTRAL_NS" -f -

# orderer-tls → orderer4-quantumleap-tls
oc get secret orderer-tls -n "$ORG_NS" -o yaml \
  | sed "s/namespace: $ORG_NS/namespace: $CENTRAL_NS/; s/name: orderer-tls/name: ${ORDERER_NAME}-${ORG}-tls/" \
  | grep -v 'uid:\|resourceVersion:\|creationTimestamp:' \
  | oc apply -n "$CENTRAL_NS" -f -

echo ""
echo "=== Verify secrets in central namespace ==="
oc get secrets -n "$CENTRAL_NS" | grep quantumleap
----

== Phase 3: Genesis Block Regeneration

[WARNING]
====
This phase causes **ordering service downtime** (~1-2 minutes). All orderers must restart with the new genesis block. The BFT cluster reforms consensus automatically once 3 of 5 orderers are active.
====

=== Step 3.1: Update configtx.yaml

Add the QuantumLeap organization definition and its orderer to the BFT consenter mapping.

[.console-input]
[source,bash]
----
cd ~/certchain-repo

# Add QuantumLeap org definition (after NeuralPath)
cat >> /dev/null  # Just showing what to add — use the sed commands below

# Insert QuantumLeap org after NeuralPath's AnchorPeers block
sed -i '/Port: 7051$/,/^$/{
  /^$/a\
\
  - \&QuantumLeap\
    Name: QuantumLeapMSP\
    ID: QuantumLeapMSP\
    MSPDir: /work/msp/quantumleap\
    OrdererEndpoints:\
      - orderer.certchain-quantumleap.svc.cluster.local:7050\
    Policies:\
      Readers:\
        Type: Signature\
        Rule: "OR('"'"'QuantumLeapMSP.admin'"'"', '"'"'QuantumLeapMSP.peer'"'"', '"'"'QuantumLeapMSP.client'"'"', '"'"'QuantumLeapMSP.orderer'"'"')"\
      Writers:\
        Type: Signature\
        Rule: "OR('"'"'QuantumLeapMSP.admin'"'"', '"'"'QuantumLeapMSP.client'"'"', '"'"'QuantumLeapMSP.orderer'"'"')"\
      Admins:\
        Type: Signature\
        Rule: "OR('"'"'QuantumLeapMSP.admin'"'"')"\
      Endorsement:\
        Type: Signature\
        Rule: "OR('"'"'QuantumLeapMSP.peer'"'"')"\
    AnchorPeers:\
      - Host: peer0.certchain-quantumleap.svc.cluster.local\
        Port: 7051
}' helm/components/certchain-central/files/configtx.yaml
----

[TIP]
====
The `sed` command above is complex. An alternative approach is to edit the file directly using the Gitea web editor or the DevSpaces IDE. The key additions are:

1. A `&QuantumLeap` organization block (identical structure to existing orgs)
2. An orderer entry in `ConsenterMapping` (ID: 5)
3. References in `CertChannelGenesis.Orderer.Organizations` and `CertChannelGenesis.Application.Organizations`
====

Add the 5th orderer to the BFT consenter mapping and add QuantumLeap to the genesis profile:

[.console-input]
[source,bash]
----
cd ~/certchain-repo

# Add orderer5 to ConsenterMapping (after orderer4/neuralpath entry)
sed -i '/ServerTLSCert: \/work\/tls\/orderer3\/server.crt$/a\
    - ID: 5\
      Host: orderer.certchain-quantumleap.svc.cluster.local\
      Port: 7050\
      MSPID: QuantumLeapMSP\
      Identity: /work/msp/quantumleap/orderers/orderer4/msp/signcerts/cert.pem\
      ClientTLSCert: /work/tls/orderer4/server.crt\
      ServerTLSCert: /work/tls/orderer4/server.crt' \
  helm/components/certchain-central/files/configtx.yaml

# Add QuantumLeap to genesis profile — Orderer Organizations
sed -i '/- \*NeuralPath$/,/Application:/{
  /- \*NeuralPath$/a\
        - *QuantumLeap
}' helm/components/certchain-central/files/configtx.yaml

# Add QuantumLeap to genesis profile — Application Organizations
sed -i '/^        - \*NeuralPath$/a\
        - *QuantumLeap' helm/components/certchain-central/files/configtx.yaml

echo "=== Verify configtx.yaml changes ==="
echo "Organizations:"
grep -c '&' helm/components/certchain-central/files/configtx.yaml
echo "ConsenterMapping entries:"
grep -c 'ID:' helm/components/certchain-central/files/configtx.yaml
echo "QuantumLeap references:"
grep -c 'QuantumLeap' helm/components/certchain-central/files/configtx.yaml
----

=== Step 3.2: Delete existing genesis and regenerate

[.console-input]
[source,bash]
----
# Delete the existing genesis ConfigMap to force regeneration
oc delete configmap fabric-genesis -n certchain

# Trigger the genesis job to re-run
# The generate-genesis job has an idempotency check — deleting the ConfigMap allows it to run
oc delete job generate-genesis -n certchain --ignore-not-found

echo "Waiting for ArgoCD to recreate the genesis job..."
echo "(ArgoCD will detect the missing job and re-create it on next sync)"
sleep 10

# Force an ArgoCD sync if needed
oc annotate application certchain-central -n openshift-gitops \
  argocd.argoproj.io/refresh=hard --overwrite

# Wait for genesis job to complete
echo "Waiting for genesis job..."
while true; do
  STATUS=$(oc get job generate-genesis -n certchain -o jsonpath='{.status.succeeded}' 2>/dev/null)
  [ "$STATUS" = "1" ] && break
  echo -n "."
  sleep 5
done
echo " Genesis block regenerated!"

# Verify
oc get configmap fabric-genesis -n certchain -o jsonpath='{.metadata.creationTimestamp}'
echo ""
----

[IMPORTANT]
====
The genesis job must have access to the QuantumLeap secrets in the central namespace. If the job fails, check that Phase 2 completed and the `orderer4-quantumleap-msp` and `orderer4-quantumleap-tls` secrets exist in the `certchain` namespace.

The `generate-genesis.sh` script and the genesis Job template must also be updated to include the new org entry in their crypto extraction loop. This requires adding a line like:

`"QuantumLeapMSP:quantumleap:orderer4:orderer4-quantumleap-msp:orderer4-quantumleap-tls"`

to the loop in `generate-genesis.sh`, and adding the corresponding volume mounts in the Job template.
====

=== Step 3.3: Restart all orderers

All orderers must restart to pick up the new genesis block (mounted via the `fabric-genesis` ConfigMap).

[.console-input]
[source,bash]
----
echo "=== Restarting all orderers ==="

# Central orderer
oc rollout restart deployment/orderer0 -n certchain

# Org orderers
for org in techpulse dataforge neuralpath quantumleap; do
  oc rollout restart deployment/orderer -n certchain-${org}
done

echo ""
echo "=== Waiting for orderers to be ready ==="
oc rollout status deployment/orderer0 -n certchain --timeout=120s
for org in techpulse dataforge neuralpath quantumleap; do
  oc rollout status deployment/orderer -n certchain-${org} --timeout=120s
done
echo "All orderers restarted!"
----

== Phase 4: Channel Operations

=== Step 4.1: Rejoin all orderers to the channel

After genesis regeneration, all orderers need to rejoin the channel with the new genesis block. Existing orderers that already have channel data will recognize the new genesis and reform consensus.

[.console-input]
[source,bash]
----
# This step runs from a pod with osnadmin and peer binaries.
# Use oc exec on the channel-setup job pod, or run a one-off pod:

oc run fabric-ops --rm -it --restart=Never \
  --image=hyperledger/fabric-tools:3.1.0 \
  --overrides='{
    "spec": {
      "serviceAccountName": "certchain-admin",
      "containers": [{
        "name": "fabric-ops",
        "image": "hyperledger/fabric-tools:3.1.0",
        "command": ["sleep", "3600"],
        "volumeMounts": [
          {"name": "genesis", "mountPath": "/channel-artifacts"},
          {"name": "orderer-tls", "mountPath": "/orderer-tls"}
        ]
      }],
      "volumes": [
        {"name": "genesis", "configMap": {"name": "fabric-genesis"}},
        {"name": "orderer-tls", "secret": {"secretName": "orderer0-tls"}}
      ]
    }
  }' -n certchain -- bash -c '
CHANNEL_NAME="certchannel"

echo "=== Joining all orderers to channel ==="
ORDERER_ADMINS=(
  "orderer0:7053"
  "orderer.certchain-techpulse.svc.cluster.local:7053"
  "orderer.certchain-dataforge.svc.cluster.local:7053"
  "orderer.certchain-neuralpath.svc.cluster.local:7053"
  "orderer.certchain-quantumleap.svc.cluster.local:7053"
)

for ADMIN_EP in "${ORDERER_ADMINS[@]}"; do
  ORDERER_NAME="${ADMIN_EP%%:*}"
  echo "--- Joining $ORDERER_NAME ---"
  osnadmin channel join \
    --channelID "$CHANNEL_NAME" \
    --config-block /channel-artifacts/genesis.block \
    -o "$ADMIN_EP" \
    --ca-file /orderer-tls/ca.crt \
    --client-cert /orderer-tls/server.crt \
    --client-key /orderer-tls/server.key 2>&1 || echo "  (may already be joined)"
done

# Wait for BFT consensus (need 3 of 5 orderers active)
echo ""
echo "Waiting for BFT consensus..."
for i in $(seq 1 30); do
  STATUS=$(osnadmin channel list --channelID "$CHANNEL_NAME" \
    -o "orderer0:7053" \
    --ca-file /orderer-tls/ca.crt \
    --client-cert /orderer-tls/server.crt \
    --client-key /orderer-tls/server.key 2>/dev/null | grep -o "\"status\":\"[^\"]*\"" | cut -d\" -f4 || echo "unknown")
  echo "  Attempt $i: status=$STATUS"
  [ "$STATUS" = "active" ] && echo "BFT consensus is active!" && break
  sleep 3
done
'
----

=== Step 4.2: Join the new peer to the channel

[.console-input]
[source,bash]
----
# Fetch genesis block and join QuantumLeap's peer
oc run fabric-peer-join --rm -it --restart=Never \
  --image=hyperledger/fabric-tools:3.1.0 \
  -n certchain -- bash -c '
CHANNEL_NAME="certchannel"
ORDERER_ENDPOINT="orderer0:7050"

# Setup paths
export FABRIC_CFG_PATH=/etc/hyperledger/fabric
export CORE_PEER_TLS_ENABLED=true

# Use QuantumLeap admin credentials
# (These would need to be mounted from secrets — simplified here)
export CORE_PEER_LOCALMSPID=QuantumLeapMSP
export CORE_PEER_MSPCONFIGPATH=/admin-msp/quantumleap
export CORE_PEER_ADDRESS=peer0.certchain-quantumleap.svc.cluster.local:7051
export CORE_PEER_TLS_ROOTCERT_FILE=/peer-tls/quantumleap/ca.crt
export ORDERER_CA=/orderer-tls/ca.crt

# Fetch genesis block from orderer
echo "Fetching genesis block..."
peer channel fetch 0 /tmp/${CHANNEL_NAME}.block \
  -o "$ORDERER_ENDPOINT" \
  -c "$CHANNEL_NAME" \
  --tls --cafile "$ORDERER_CA"

# Join peer to channel
echo "Joining peer0 (quantumleap) to channel..."
peer channel join -b /tmp/${CHANNEL_NAME}.block
echo "Peer joined successfully!"

# Verify
peer channel list
'
----

[NOTE]
====
The commands above are simplified for clarity. In practice, the fabric-ops pod needs volume mounts for:

- `quantumleap-admin-msp` secret (from central namespace)
- `peer0-quantumleap-tls` secret (from central namespace)
- `orderer0-tls` secret (for orderer connection)
- `fabric-genesis` ConfigMap

The existing `channel-setup-job.yaml` template mounts all org secrets. For a permanent solution, update the Job template to include QuantumLeap.
====

== Phase 5: Chaincode Lifecycle

The chaincode endorsement policy must be updated to include the new org. This requires a new sequence number and approval from all orgs.

=== Step 5.1: Install chaincode on new peer

[.console-input]
[source,bash]
----
# The CcaaS package is org-independent (same connection.json pointing to certcontract:7052)
# Install the existing package on QuantumLeap's peer

# Get the existing package ID
PACKAGE_ID=$(oc get configmap chaincode-id -n certchain -o jsonpath='{.data.package-id}')
echo "Existing package ID: $PACKAGE_ID"

# Install on QuantumLeap's peer (from a fabric-tools pod with QL admin creds)
# peer lifecycle chaincode install /work/certcontract.tar.gz
----

=== Step 5.2: Approve chaincode for all orgs with updated policy

The endorsement policy must include the new org. **All orgs** must approve with the same policy at the next sequence number.

[.console-input]
[source,bash]
----
# Determine next sequence number
CURRENT_SEQ=$(peer lifecycle chaincode querycommitted \
  --channelID certchannel --name certcontract 2>/dev/null \
  | grep -oP 'Sequence: \K[0-9]+')
NEXT_SEQ=$((CURRENT_SEQ + 1))
echo "Current sequence: $CURRENT_SEQ, next: $NEXT_SEQ"

# Updated signature policy includes QuantumLeap
POLICY="OR('TechPulseMSP.peer','DataForgeMSP.peer','NeuralPathMSP.peer','QuantumLeapMSP.peer')"

# Approve for EACH org (run once per org, switching MSP context each time)
for ORG_MSP in TechPulseMSP DataForgeMSP NeuralPathMSP QuantumLeapMSP; do
  echo "--- Approving for $ORG_MSP ---"
  # Set CORE_PEER_* environment for this org...
  peer lifecycle chaincode approveformyorg \
    --channelID certchannel \
    --name certcontract \
    --version 1.0 \
    --package-id "$PACKAGE_ID" \
    --sequence $NEXT_SEQ \
    --signature-policy "$POLICY" \
    --orderer orderer0:7050 \
    --tls --cafile /orderer-tls/ca.crt
done
----

=== Step 5.3: Commit updated chaincode definition

[.console-input]
[source,bash]
----
# Commit requires endorsement from MAJORITY of orgs
# With 4 orgs, need 3 of 4 (75%)
peer lifecycle chaincode commit \
  --channelID certchannel \
  --name certcontract \
  --version 1.0 \
  --sequence $NEXT_SEQ \
  --signature-policy "$POLICY" \
  --orderer orderer0:7050 \
  --tls --cafile /orderer-tls/ca.crt \
  --peerAddresses peer0.certchain-techpulse.svc.cluster.local:7051 \
  --tlsRootCertFiles /work/peer-tls-techpulse/ca.crt \
  --peerAddresses peer0.certchain-dataforge.svc.cluster.local:7051 \
  --tlsRootCertFiles /work/peer-tls-dataforge/ca.crt \
  --peerAddresses peer0.certchain-neuralpath.svc.cluster.local:7051 \
  --tlsRootCertFiles /work/peer-tls-neuralpath/ca.crt \
  --peerAddresses peer0.certchain-quantumleap.svc.cluster.local:7051 \
  --tlsRootCertFiles /work/peer-tls-quantumleap/ca.crt

echo "Chaincode committed with updated policy at sequence $NEXT_SEQ"
----

== Phase 6: Identity Brokering

Register QuantumLeap's Keycloak as an identity provider in central Keycloak.

[.console-input]
[source,bash,subs="attributes"]
----
CENTRAL_KC="https://keycloak-certchain.{cluster_domain}"
ORG_KC="https://keycloak-certchain-quantumleap.{cluster_domain}"
ORG="quantumleap"
DISPLAY_NAME="QuantumLeap Labs"

# Get central KC admin token
ADMIN_TOKEN=$(curl -sk -X POST "${CENTRAL_KC}/realms/master/protocol/openid-connect/token" \
  -d "username=admin" -d "password=admin" -d "grant_type=password" -d "client_id=admin-cli" \
  | python3 -c "import sys,json; print(json.load(sys.stdin)['access_token'])")

# Get org KC admin token
ORG_TOKEN=$(curl -sk -X POST "${ORG_KC}/realms/master/protocol/openid-connect/token" \
  -d "username=admin" -d "password=admin" -d "grant_type=password" -d "client_id=admin-cli" \
  | python3 -c "import sys,json; print(json.load(sys.stdin)['access_token'])")

# Update broker-client redirect URIs on org KC
BC_UUID=$(curl -sk "${ORG_KC}/admin/realms/${ORG}/clients?clientId=broker-client" \
  -H "Authorization: Bearer ${ORG_TOKEN}" \
  | python3 -c "import sys,json; print(json.load(sys.stdin)[0]['id'])")

curl -sk -X PUT "${ORG_KC}/admin/realms/${ORG}/clients/${BC_UUID}" \
  -H "Authorization: Bearer ${ORG_TOKEN}" -H "Content-Type: application/json" \
  -d "{\"redirectUris\":[\"${CENTRAL_KC}/realms/certchain/broker/${ORG}/endpoint\",\"${CENTRAL_KC}/realms/certchain/broker/${ORG}/endpoint/*\"]}"

# Create IDP broker in central KC
curl -sk -X POST "${CENTRAL_KC}/admin/realms/certchain/identity-provider/instances" \
  -H "Authorization: Bearer ${ADMIN_TOKEN}" -H "Content-Type: application/json" \
  -d "{
    \"alias\":\"${ORG}\",\"displayName\":\"${DISPLAY_NAME}\",\"providerId\":\"oidc\",
    \"enabled\":true,\"trustEmail\":true,\"storeToken\":false,
    \"firstBrokerLoginFlowAlias\":\"auto-idp-link\",\"hideOnLogin\":false,
    \"config\":{
      \"clientId\":\"broker-client\",\"clientSecret\":\"broker-secret-${ORG}\",
      \"tokenUrl\":\"${ORG_KC}/realms/${ORG}/protocol/openid-connect/token\",
      \"authorizationUrl\":\"${ORG_KC}/realms/${ORG}/protocol/openid-connect/auth\",
      \"logoutUrl\":\"${ORG_KC}/realms/${ORG}/protocol/openid-connect/logout\",
      \"userInfoUrl\":\"${ORG_KC}/realms/${ORG}/protocol/openid-connect/userinfo\",
      \"jwksUrl\":\"${ORG_KC}/realms/${ORG}/protocol/openid-connect/certs\",
      \"issuer\":\"${ORG_KC}/realms/${ORG}\",
      \"validateSignature\":\"true\",\"useJwksUrl\":\"true\",\"syncMode\":\"IMPORT\"
    }
  }"

# Create Organization and link IDP
curl -sk -X POST "${CENTRAL_KC}/admin/realms/certchain/organizations" \
  -H "Authorization: Bearer ${ADMIN_TOKEN}" -H "Content-Type: application/json" \
  -d "{\"name\":\"${ORG}\",\"alias\":\"${ORG}\",\"enabled\":true,\"description\":\"${DISPLAY_NAME}\",\"domains\":[{\"name\":\"${ORG}.demo\",\"verified\":true}]}"

ORG_ID=$(curl -sk "${CENTRAL_KC}/admin/realms/certchain/organizations?search=${ORG}" \
  -H "Authorization: Bearer ${ADMIN_TOKEN}" | python3 -c "import sys,json; print(json.load(sys.stdin)[0]['id'])")

curl -sk -X POST "${CENTRAL_KC}/admin/realms/certchain/organizations/${ORG_ID}/identity-providers" \
  -H "Authorization: Bearer ${ADMIN_TOKEN}" -H "Content-Type: application/json" \
  -d "\"${ORG}\""

echo "Identity brokering configured for ${DISPLAY_NAME}!"
----

cd ~/certchain-repo

  orderer4-quantumleap-msp orderer4-quantumleap-tls -n certchain

# Regenerate genesis without QuantumLeap (delete ConfigMap, re-run job)
oc delete configmap fabric-genesis -n certchain
oc delete job generate-genesis -n certchain
# ArgoCD will recreate the job with the original configtx.yaml

# Restart orderers to use original genesis
oc rollout restart deployment/orderer0 -n certchain
for org in techpulse dataforge neuralpath; do
  oc rollout restart deployment/orderer -n certchain-${org}
done
